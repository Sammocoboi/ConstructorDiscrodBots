## 3. Что делаем вместе (и как не мешать друг другу)

| Работа | Ответственный | Участники | Правило |

| Контракт конфигурации бота (JSONB) | Шухратжон | Артём, Саня, Данила | Фиксируем в `docs/config-schema.md` до начала кодинга, меняем только через PR |

| Тестовый Discord-сервер и бот | Шухратжон | Саня | Создать до начала работ по ботам, без него не проверить FR-4.5 |

## 4. Порядок работ по зависимостям

Не календарь, а последовательность: что без чего не имеет смысла делать.

**Этап 0. Фундамент (без него никто не начнёт)**

1. Структура репозитория, Docker Compose, PostgreSQL, `.env`.
2. Контракты в `docs/`: API, config-schema, block-registry, module-manifest, runtime-protocol.
3. Модель данных и миграции.
4. Каркас React + API-клиент.
5. Тестовый Discord-сервер и приложение.

**Этап 1. Ядро**

6. Auth (Discord OAuth + email, JWT, сессии) → профиль.
7. CRUD ботов, шифрование токенов, мастер подключения, invite.

12. Интерпретатор: триггеры, условия, действия.
13. UI модулей и команд.

**Этап 3. Редактор**

14. React Flow, палитра, панель свойств, autosave.
15. Блоки логики и данных, переменные, валидация.
16. Тест с трассировкой и dry-run.
17. Редактор сообщений и эмбедов.

**Этап 4. Контент**

18. 70 команд библиотеки.
19. 8 системных шаблонов.
20. Пользовательские шаблоны, импорт/экспорт, share-link.

**Этап 5. Деньги и админка**

21. Stripe, тарифы, лимиты, usage.

**Этап 6. Качество и сдача**

## 5. Приоритеты: что обязательно, что можно урезать

ТЗ рассчитано на 6–7 человек. На четверых полный объём — риск. Делим на P0/P1/P2 по важности для защиты, а не по срокам.

### P0 — без этого нет проекта

- Auth (Discord + email), профиль, JWT.
- Создание бота, токен, invite, запуск/остановка, статус.
- 8 системных шаблонов и создание бота из шаблона.
- 70 команд библиотеки (можно 40–50, если совсем горит, но в ТЗ критерий 70).
- Редактор графа: базовые триггеры, условия, действия, сохранение, публикация.
- Редактор сообщений/эмбедов с предпросмотром.
- Модули: приветствия, модерация, роли (минимум 3).
- Runtime: Gateway, интерпретатор, hot reload, статусы.
- Тарифы и лимиты (Stripe в тестовом режиме).
- Django Admin.
- Docker + CI + тестовый Discord-сервер.

### P1 — сильно повышает оценку

- Тест сценария с трассировкой и dry-run.
- Версии, diff, откат (30 версий).
- Пользовательские шаблоны, импорт/экспорт, share-link.
- Простой режим «Когда → Если → Тогда».
- Проверка прав бота и порядка ролей.
- Уведомления на email.
- E2E-тесты ключевых сценариев.
- i18n RU/EN, тёмная/светлая тема.

### P2 — можно перенести на «после защиты» / этап 2

- Полный набор из 15+ модулей.
- Шардирование Runtime, 1000 ботов, нагрузочные тесты на полную.
- Все 5 типов параметров с autocomplete и локализациями.
- Промокоды, trial, пропорциональный пересчёт Stripe.
- WCAG 2.1 AA полностью.
- Публичный каталог шаблонов, маркетплейс, 2FA, мобильное приложение, музыка, публичный API — **явно вне MVP по ТЗ**.

## 7. Контракты, которые фиксируем до начала кодинга

Без этого фронтенд, backend и Runtime начнут расходиться.

1. **`docs/api-contract.md`** — префикс `/api/v1/`, формат ошибок `{code, message, details, request_id}`, курсорная пагинация, коды ответов.
2. **`docs/config-schema.md`** — версия схемы, `profile`, `modules`, `commands`, `flows`, `messages`, `variables_schema`; лимит 2 МБ; запрет секретов.
3. **`docs/block-registry.md`** — типы блоков, параметры, входы/выходы, ограничения; один JSON для Runtime и UI.
4. **`docs/module-manifest.md`** — id, title, permissions, intents, commands, events, settings JSON Schema.
5. **`docs/runtime-protocol.md`** — таблицы `runtime_commands`, `bot_runtime_state`, LISTEN/NOTIFY, heartbeat, коды ошибок.
6. **Типы фронтенда** генерируются из OpenAPI, руками не дублируются.

**Правило изменения контракта:** PR в `docs/` → согласование владельца → только потом код.

## 8. Git-процесс на 4 человека

- `main` — защищена, только через PR.
- Ветки: `feat/artem-auth`, `feat/sanya-bot-wizard`, `feat/shu-runtime`, `feat/danila-editor`.
- Коммиты: `feat:`, `fix:`, `docs:`, `test:`, `chore:`.
- PR: не больше ~400 строк, 1 approve (Артём или владелец подсистемы), CI зелёный.
- Миграции БД — только Артём или по его ревью.
- Секреты — только в `.env`, `.env.example` в репозитории, pre-commit secret scan.
- Каждый крупный этап — тег и короткий changelog.

**Чтобы не конфликтовать в файлах:**

- backend: приложения по доменам (`accounts/`, `bots/`, `modules/`, `commands/`, `billing/`, `templates/`);
- frontend: `features/<feature>/` + `shared/`;
- Runtime — отдельный каталог `runtime/`, не импортирует Django-модели напрямую;
- контент команд и шаблонов — JSON-файлы в `content/`, не в коде.

## 9. Definition of Done (общее)

Задача считается сделанной, если:

- код в PR, CI зелёный, есть ревью;
- есть тесты на бизнес-логику (backend — pytest, frontend — Vitest, E2E — Playwright);
- API описан в OpenAPI, типы фронта обновлены;
- учтены лимиты и ошибки Discord;
- нет секретов в коде и логах;
- обновлена документация/ADR, если менялся контракт;
- проверено на тестовом Discord-сервере (для ботовых фич);
- работает пустое/загрузочное/ошибочное состояние (для UI).
