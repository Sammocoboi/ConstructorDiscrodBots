# 0006. Идемпотентность API и Stripe webhook

- Статус: принято
- Дата: 2026-10-21

## Контекст

Повторные запросы из-за retry, двойного клика и сетевых ошибок создают дубли ботов и
платежей. Stripe может доставлять одно и то же событие несколько раз.

## Решение

- Клиентский заголовок `Idempotency-Key` для аутентифицированных mutating-запросов.
- Запись в `idempotency_keys`: пользователь, ключ, отпечаток запроса (метод + путь + тело),
  сохранённый статус и JSON-ответ; TTL 24 часа.
- Повтор с тем же отпечатком возвращает сохранённый ответ (`Idempotent-Replayed: true`).
- Повтор с другим отпечатком — `409 idempotency_conflict`.
- Stripe webhook проверяет подпись и идемпотентно создаёт подписку/платёж/счёт через
  `get_or_create` по внешнему идентификатору.

## Последствия

- Нужна периодическая очистка `idempotency_keys`.
- Ключ не заменяет транзакции и уникальные ограничения — они остаются последней линией защиты.
- Webhook без настроенной подписи принимается только в dev/staging.
