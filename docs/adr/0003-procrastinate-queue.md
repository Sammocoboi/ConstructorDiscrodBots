# 0003. Очередь Procrastinate на PostgreSQL

- Статус: принято
- Дата: 2026-10-21

## Контекст

Нужны фоновые задачи: email, синхронизация slash-команд, очистка usage и idempotency,
регрессия шаблонов. Инфраструктура уже содержит PostgreSQL; отдельный Redis/RabbitMQ
усложняет деплой и бэкапы.

## Решение

Использовать Procrastinate — очередь на PostgreSQL с `LISTEN/NOTIFY`, транзакционной
постановкой задач и веб-интерфейсом мониторинга.

## Последствия

- Нет отдельного брокера; задачи и бизнес-данные в одной транзакции.
- Нагрузка на PostgreSQL растёт — очереди выделяются в отдельную схему, пул соединений ограничивается.
- При росте до 1000 ботов возможен переход на внешний брокер; интерфейс постановки задач изолирован.
